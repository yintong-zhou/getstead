# M2 Net worth — implementation plan

Spec (PROJECT.md): assets minus liabilities; monthly snapshot; trend chart. Branch `migrate/prisma-postgres`, on top of `0d4e178`.

## Decisions

- **Balance checks, not stored snapshots.** Accounts have no opening balance today. Add a dated "balance check" per account: the account's balance at the end of that day. Month-end net worth is computed from checks + movements, so editing an old movement or check fixes history automatically. No frozen snapshot table.
- **Balance rule** (pure function): balance of account A at date D = latest check of A with `asOf <= D`, plus the sum of non-voided movements of A with `asOf < bookingDate <= D`. With no check, the sum of all non-voided movements with `bookingDate <= D` (starting at 0). Movements on the check date are already inside the check. Transfer legs count (they move money between accounts).
- **Signs.** Balances are signed integer cents in EUR. Debts and card balances owed are negative. Assets = sum of positive account balances, liabilities = sum of negative ones (shown as a positive number), net worth = sum of all.
- **Archived accounts** are included (history needs them). The UI hints to record a 0 check when closing an account; an archived account with a non-zero current balance is shown flagged.
- **Monthly snapshot** = net worth at each month end for the last 12 months; the current month uses today.
- No new dependencies. Chart is inline SVG (line with faded area, per brand-guidelines.md).

## Steps

1. **Schema + migration** (`db/schema.prisma`, `db/migrations/20261121090000_net_worth/migration.sql`)
   - Model `BalanceCheck` → table `stead_balance_checks`: `check_id` uuid PK, `user_id`, `account_id`, `as_of` date, `balance_cents` int (zero allowed, `|x| <= 1_000_000_000` via CHECK), `created_at`.
   - FK `(user_id, account_id)` → `stead_accounts(user_id, account_id)` ON DELETE RESTRICT, FK `user_id` → users. `@@unique([userId, accountId, asOf])`, `@@unique([userId, id])`, index `(user_id, account_id, as_of)`.
   - `db/grant-runtime.sql`: `GRANT SELECT, INSERT, UPDATE (balance_cents), DELETE ON public.stead_balance_checks TO stead_auth_app;` in a new "Net worth (M2)" block.
2. **Pure calc** `server/net-worth/calc.ts` + `calc.test.ts` (node:test, synthetic data)
   - `balanceAt(checks, movements, date)` and `netWorthAt(accounts, checks, movements, date) -> { assetsCents, liabilitiesCents, netCents, perAccount }`.
   - Tests: no checks; check then movements after; movement on the check date excluded; voided ignored; later check overrides; debt negative goes to liabilities; month-end series.
3. **Service** `server/net-worth/service.ts` (every query scoped by `userId`)
   - `listChecks(userId)`, `recordCheck(userId, input)` (Reader: `accountId` uuid, `asOf` date not after Rome today, `balanceCents` signed int incl. 0 — add `Reader.signedCents` allowing 0 in `server/cash-flow/validate.ts`); upsert on `(userId, accountId, asOf)`; account must belong to the user (FK guarantees, P2003 → 409).
   - `deleteCheck(userId, id)`.
   - `getNetWorth(userId, now)`: load accounts (incl. archived), checks, non-voided movements up to today (select only `accountId, bookingDate, amountCents`); return current totals, per-account rows (name, type, archived, balance, last check date), 12-month series `{ month, netCents, assetsCents, liabilitiesCents }`, change vs previous month end.
   - Decrypting descriptions is not needed; never log amounts.
4. **API** (reuse `api()` from `server/cash-flow/http.ts`, `paramId`)
   - `app/api/net-worth/route.ts`: `GET` → `getNetWorth`.
   - `app/api/net-worth/balances/route.ts`: `GET` list, `POST` record (201).
   - `app/api/net-worth/balances/[id]/route.ts`: `DELETE` (204).
   - `components/cash-flow/api.ts` `call()` prefixes `/api/cash-flow`; add an optional base or a sibling for `/api/net-worth` (smallest change).
5. **UI**
   - Page `app/[locale]/net-worth/page.tsx` following `app/[locale]/accounts/page.tsx` (readPageUser, UnavailableNotice).
   - `components/net-worth/net-worth-view.tsx` (client): hero card (brand-dark, net worth, change chip vs last month), assets/liabilities row, 12-month SVG trend with accessible `aria-label` text, per-account list, "Record balance" form (account select, date default today, amount via `parseLimit` + an "owed / liability" checkbox defaulting on for DEBT and CARD), recent checks list with delete. Use `useAction`/`NoticeLine`.
   - Copy EN + IT in `components/net-worth/copy.ts` (or extend `cashFlowCopy` if errors/fields map is needed — reuse its `errors`).
   - Nav: add `net-worth` section to `components/app-shell.tsx` (label in `dashboard-copy.ts`: "Net worth" / "Patrimonio"), icon in `components/icon.tsx`.
   - Dashboard: small net worth card linking to the page (`getDashboard` gets `netWorthCents`).
   - Mobile: must work at 320 px.
6. **Integration test** in `server/cash-flow/postgres.integration.ts` (or new `server/net-worth/postgres.integration.ts` added to `test:postgres`): runtime role can insert/update/delete checks; another user's account id is rejected; user B never sees user A's checks or totals.
7. **Docs**: README section for net worth; note the balance-check rule.
